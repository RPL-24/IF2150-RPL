## B.3 Kendala dan Catatan Penting

**Catatan Penting**

*Menjalankan Aplikasi*
- Aplikasi memakai Supabase. File `.env.local` diisi dari `.env.example`, dengan nilai `NEXT_PUBLIC_SUPABASE_URL` dan `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` yang akan diberikan kelompok kami kepada asisten. Kunci rahasia (`SUPABASE_SECRET_KEY`) hanya dipakai skrip seed dan tidak dibutuhkan untuk menjalankan aplikasi.
- Akun uji (tercantum di [`src/README.md`](../../src/README.md)): `warga1@laporkota.test`, `warga2@laporkota.test`, `admin@laporkota.test`, `eksekutor@laporkota.test`.
- Data uji dapat dikembalikan ke kondisi awal dengan `npm run seed`.

*Kendala*
- Lokasi yang ditampilkan hanya berupa koordinat, peta, dan link Google Maps. Database tidak menyimpan alamat dalam wujud teks.
- Jika pengiriman "HasilPerbaikan" gagal setelah foto/video terunggah, berkas tersebut tetap tertinggal di bucket `media`. Hal yang sama berlaku untuk laporan warga (UC01), karena berkas diunggah dari browser sebelum `kirimLaporan` dipanggil; termasuk saat token anti-bot ditolak, sebab token baru diverifikasi di server setelah media masuk Storage. Storage sendiri tidak dilindungi anti-bot (hanya dibatasi policy unggah per pengguna). Belum ada pembersihan otomatis.
- Filter Daftar Tugas hanya berdasarkan kategori; filter lokasi tidak diimplementasikan.
- Environment production dan lokal memakai key uji Cloudflare yang selalu lolos verifikasi, sehingga alur anti-bot sudah berjalan tetapi belum memberi perlindungan nyata. Untuk penggunaan sebenarnya, key perlu diganti dengan key asli dari dashboard Cloudflare.
- Deploy ke Vercel dilakukan manual lewat Vercel CLI (folder proyek di-*link* lewat `.vercel/`); repository tidak terhubung ke integrasi Git Vercel, sehingga merge ke `dev`/`main` tidak otomatis men-*deploy*.
- Supabase Advisors (performa) melaporkan *Multiple Permissive Policies* pada 6 tabel yang belum ditangani: `laporan`, `profiles`, `upvote`, `hasil_perbaikan` (SELECT) serta `foto`, `video` (INSERT). Semua policy per peran pada aksi yang sama dievaluasi; hasilnya benar, tetapi bisa digabung menjadi satu policy per aksi.
- Supabase JS tidak punya transaksi lintas *request*. Penyimpanan laporan/hasil perbaikan beserta foto/video dipindah ke RPC PostgreSQL yang berjalan dalam satu transaksi (`kirim_laporan`, `kirim_hasil_perbaikan`), agar tidak ada laporan tanpa bukti.
- KNF13 (notifikasi email ≤ 2 menit) tidak diimplementasikan dalam bentuk email; sesuai Batasan SKPL 2.4 poin 8, notifikasi hanya muncul di aplikasi (lihat B.1 no. 49).
- Event Realtime hanya membawa kolom tabel `notifikasi` (tanpa `id_tiket`), sehingga lonceng memuat ulang daftar notifikasi lewat `NotifikasiController.ambilNotifikasi()` setiap ada event.
- Browser sering memberi MIME kosong untuk berkas `.mkv`, sedangkan bucket memeriksa MIME. `unggahMedia()` (`src/lib/media.ts`) mengirim `contentType` eksplisit dari ekstensi berkas.
- Leaflet membutuhkan objek `window` dan tidak bisa dirender di server; `MapView` dimuat dengan `next/dynamic` (`ssr: false`).
- Supabase CLI v3 menjadikan database lokal sebagai target default, sehingga perintah ke project memakai `--remote` (`npx supabase db push --remote`, `npx supabase gen types --remote`).

*Catatan tambahan untuk asisten*
- Opsi *Confirm email* Supabase Auth dimatikan, sehingga akun yang didaftarkan lewat `/daftar` langsung bisa dipakai (selalu berperan Warga). Akun Tim Administrasi dan Eksekutor hanya dibuat lewat seed.
- Aplikasi di-*deploy* di <https://laporkota.vercel.app>, tetapi tetap bisa dijalankan lokal mengikuti [`src/README.md`](../../src/README.md), termasuk dengan project Supabase sendiri (migration di `supabase/migrations/` lalu `npm run seed`).
