### Catatan

| Catatan |
| --- |
| 1. deskripsi umum sistem: yang dibahas beda dengan milestone sebelumnya. Di M2, definisi solusi secara overall, bahas fitur, alur/flow secara naratif (berurutan), mirip kaya activity diagram tapi deskripsi (kata2nya dibagusin). Bahas ekspetasi user, CONTOH: 'mahasiswa mendapat lingkungan belajar lebih interaktif', 'tutor bisa dapet uang tambahan' dan harapan akhir dari software  |
| 2. Deskripsi user software: boleh disamain M1. Sistem itu bukan Aktor. UTS taun lalu 'Sistem tuh apa?' |
| 3. Penggunaan kata diperbaiki|
| 4. Kebutuhan pengguna awal, udah oke karena ga ada sistem. User Story itu fokus spesifik ngomongin suatu hal, tapi biasanya User Story dapet dari wwc dan lebih luas. |
| 5. User Story -> Goal -> Activity -> Action(sifatnya lebih ke langkah-langkah). Misal activity: melakukan regis, aksi: klik create account, ngisi form, klik submit|
| 6. Deskripsi aktivitas dilengkapin (sesuai model proses bisnis) |
| 7. Aktivitas di awalin kata kerja aktif (me-)|
| 8. setiap activity dihubungin minimal salah satu dari (user,business,system), bisa fokus ke user story. Aturan undang-undang /solusi didefinisi ke business |
| 9. Untuk setiap kebutuhan yang telah diidentifikasi sebagai "didukung oleh perangkat lunak", buatlah daftar kebutuhan fungsional P/L|
| 10. Setiap aktivitas harus atomic |
| 11. KF/NKF bisa mencakup beberapa R(id kebutuhan) |
